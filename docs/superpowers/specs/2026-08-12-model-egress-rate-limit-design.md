# OrionaMesh 请求限流与模型出口设计

## 目标与范围

本设计同步功能规格 FR-026～FR-029 与 SC-008。MVP 将请求限流和外部模型出口实现为后端
代码库内的基础设施模块，不新增独立网络服务或部署单元。FastAPI API 与 Celery worker 共用
相同策略、配置和审计组件，业务服务不得直接调用外部模型供应商。

## 请求限流

- Redis 保存分布式限流计数，计数更新必须原子化；算法采用滑动窗口或语义等价实现。
- 认证接口同时应用来源 IP 和规范化目标账号两个限流键；任一超限即拒绝。
- 上传、问答和普通认证接口使用当前认证用户作为限流键。
- 默认阈值分别为：认证每 IP 20 次/5 分钟且每账号 5 次/5 分钟；上传每用户
  10 次/10 分钟；问答每用户 20 次/分钟；其他接口每用户 120 次/分钟。
- 阈值和窗口均由环境配置覆盖。超限统一返回 HTTP 429、业务码
  `10005 RATE_LIMIT_EXCEEDED`、固定用户提示和 `Retry-After`，拒绝路径不得创建业务副作用。

## 统一模型出口网关

后端内部 `model_gateway` 是 Embedding、Query Rewrite、Reranker 和回答生成的唯一外部模型
调用入口。网关集中执行：

1. 根据调用类型装配最小必要内容。
2. 执行敏感数据检测和脱敏。
3. 根据配置选择供应商、端点和模型，并在发送时注入凭证。
4. 应用各调用类型既定的超时、重试和降级策略。
5. 记录严格白名单内的调用元数据。

供应商 SDK 和 HTTP 客户端只能在网关供应商适配层中导入。API、worker、领域服务和现有
LangChain 适配器只能依赖网关协议；通过架构测试阻止旁路依赖。

## 数据边界与脱敏

- 发送到外部供应商的内容必须限制为完成当前调用所需的最小文本和结构字段。
- 禁止外发密码、访问/刷新令牌、密钥、Authorization/Cookie 等请求头、内部存储路径及
  可直接识别租户的内部标识。
- 邮箱、电话号码、身份证件号等个人标识按统一策略替换为不可逆占位符；占位符仅在当前
  调用范围内用于保持语义一致，不建立可逆映射。
- 脱敏组件异常或检测到禁止外发内容但无法可靠脱敏时采用 fail-closed：不得产生外部网络
  请求，并按调用类型降级或收敛为明确失败。
- 供应商凭证只在发送边界注入，不进入领域对象、任务 payload 或调用日志。

## 日志与审计

调用日志只允许记录：`trace_id`、调用 ID、不可逆用户/租户标识、调用类型、供应商、模型、
开始/结束时间、耗时、状态、错误分类、重试次数、输入/输出 token 数量和载荷字节数。

禁止记录请求或响应正文、提示词、用户问题、资料片段、文件名、请求头、凭证及其可逆摘要；
脱敏后的正文也不得记录。异常对象进入日志前必须由统一过滤器处理。

## 错误与降级

- 限流：返回 `10005/429` 和 `Retry-After`。
- 脱敏拒绝或网关不可用：Query Rewrite 回退原问题；Reranker 回退 RRF；Embedding 使当前
  任务按既定重试后明确失败；回答生成重试后将消息收敛为 `cancelled`。
- 外部供应商错误不得向用户暴露供应商名称、原始响应或敏感请求内容，只返回稳定业务错误
  和 `trace_id`。

## 验证

- 限流契约测试验证四类阈值、双重认证键、`Retry-After`、固定业务码和零业务副作用。
- Redis 集成测试验证跨进程共享计数、窗口恢复和原子并发行为。
- 架构测试验证除网关适配层外没有供应商 SDK、外部模型 HTTP 客户端或直接 LangChain
  供应商调用。
- 出口测试使用受控假供应商，验证所有调用经过网关、脱敏失败无网络请求、凭证仅在发送边界
  注入，并且日志仅包含白名单元数据。
