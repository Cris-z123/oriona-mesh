# 功能规格：OrionaMesh 个人知识库 RAG MVP

**功能分支**：`001-orionamesh-rag-mvp`  
**创建日期**：2026-08-11  
**状态**：草稿  
**输入**：基于 `docs/OrionaMesh.md` 创建 OrionaMesh 个人知识库 RAG MVP 功能规格。

## 澄清

### 会话 2026-08-12

- 问：MVP 是否交付资料重新处理或替换功能？→ 答：否；仅保留版本一致性骨架，面向用户的重新处理与替换接口延期至 Phase 2。
- 问：上传资料是否有明确的大小限制？→ 答：是；单个资料最大 50MB，超限请求必须被拒绝并说明原因。
- 问：MVP 是否支持忘记密码或自助密码重置？→ 答：否；不提供忘记密码、邮件重置或验证码重置流程。
- 问：单次批量上传最多包含多少个文件？→ 答：20 个文件。
- 问：删除资料后如何处理历史回答中的来源信息？→ 答：保留来源快照供核验，但不允许访问或恢复原始资料。
- 问：MVP 中资料处理失败后用户可执行什么操作？→ 答：查看失败原因并删除资料；不提供重新处理或替换。
- 问：MVP 是否允许不绑定知识库的纯聊天对话？→ 答：否；每个对话必须绑定一个用户有权访问的知识库。
- 问：MVP 采用哪种请求限流策略？→ 答：采用可配置的分级限流；认证接口按 IP 与账号限制，上传和问答按当前用户限制，普通接口使用较宽阈值；超限统一返回 HTTP 429、固定业务错误码和 `Retry-After`。
- 问：分级限流采用哪组默认阈值？→ 答：注册/登录每来源 IP 20 次/5 分钟且每规范化邮箱摘要 5 次/5 分钟；刷新每来源 IP 20 次/5 分钟且每 refresh token HMAC 指纹 5 次/5 分钟；上传每用户 10 次/10 分钟；问答每用户 20 次/分钟；其他已认证接口每用户 120 次/分钟，全部允许通过配置覆盖。
- 问：SC-001～SC-007 的量化指标是否属于自动化交付门禁？→ 答：否；它们仅作为产品成功指标，不建立固定评测集、比例断言、性能阈值门禁或发布阻断条件，相关功能行为仍按 FR 和用户故事进行确定性测试。
- 问：统一出口网关承担哪些职责？→ 答：所有外部 Embedding、Query Rewrite、Reranker 和回答生成调用必须经过统一出口网关；网关集中负责供应商路由、凭证注入、数据脱敏、超时、重试、降级和调用元数据审计，业务服务及模型适配器不得绕过网关直连外部供应商。
- 问：脱敏失败时如何处理外部调用？→ 答：采用默认拒绝策略；检测到禁止发送的敏感数据且无法可靠脱敏，或脱敏组件异常时，不得向外部供应商发送请求；只记录不含原文的失败元数据，并按调用类型降级或收敛为明确失败。
- 问：外部模型调用日志允许记录哪些元数据？→ 答：采用严格白名单，只允许记录 `trace_id`、调用 ID、经不可逆处理的用户/租户标识、调用类型、供应商、模型、开始/结束时间、耗时、状态、错误分类、重试次数、输入/输出 token 数量和载荷字节数；禁止记录请求或响应正文、提示词、用户问题、资料片段、文件名、请求头及凭证。

## 用户场景与测试（必填）

### 用户故事 1：建立并维护私有知识库（优先级：P1）

作为已登录用户，我可以创建个人知识库、批量上传支持的文本类资料，并清楚看到每份资料
的处理结果，以便将自己的资料转化为可用的私有知识库。

**优先级理由**：资料进入知识库并保持用户隔离，是后续可信问答的前提，也是 MVP 的核心
价值入口。

**独立测试**：用户创建知识库后上传多份支持的资料，能够看到每份资料进入明确的最终
状态，并且其他用户无法查看或操作这些资料。

**验收场景**：

1. **假如** 用户已登录，**当** 创建知识库并上传一份支持的资料，**那么** 系统保存资料
   并显示可理解的处理进度和最终结果。
2. **假如** 用户上传多份资料，**当** 其中一份处理失败，**那么** 失败资料显示失败原因及
   删除操作；其他资料的处理不受影响。
3. **假如** 用户尝试访问另一用户的知识库或资料，**当** 发起查看、更新或删除操作，
   **那么** 系统拒绝该操作且不泄露资源信息。

---

### 用户故事 2：基于资料进行可信连续问答（优先级：P2）

作为知识库所有者，我可以在必须绑定知识库的对话中连续提问，获得带来源引用的回答，
并能回看历史消息，以便核验回答内容并持续探索自己的资料。

**优先级理由**：带引用的问答将已处理资料转化为用户可直接获得的价值，是产品区别于
通用聊天工具的关键。

**独立测试**：用户在包含已完成资料的知识库中提问，能获得基于资料的回答和可打开的
来源信息；在没有相关资料时，系统明确说明未找到证据而非编造回答。

**验收场景**：

1. **假如** 知识库中存在相关且已完成处理的资料，**当** 用户发送问题，**那么** 系统以
   流式方式返回回答，并为回答提供来源文件及其定位信息。
2. **假如** 问题没有可用资料证据，**当** 用户发送问题，**那么** 系统明确告知知识库中
   未找到相关内容，并提示用户换一种问法或检查资料处理状态。
3. **假如** 用户已进行多轮对话，**当** 用户继续追问，**那么** 系统保留对话历史，并在
   不超出当前知识库边界的前提下理解追问。

---

### 用户故事 3：掌握资料处理与异常结果（优先级：P3）

作为知识库所有者，我可以查看资料的处理详情、失败原因和处理记录，并能删除资料，
以便在资料处理异常时掌握其结果，并维护知识库的可靠性。

**优先级理由**：可诊断的处理状态与可控的资料生命周期，保证知识库不会因失败或旧内容
而悄然失真。

**独立测试**：用户查看一份处理中、失败或已完成资料的详情；在处理异常后能够看到明确
结果，且问答不使用未完成、失败或已删除的资料内容。

**验收场景**：

1. **假如** 资料处理被中断或重试耗尽，**当** 用户查看资料或任务详情，**那么** 系统显示
   明确失败结果和诊断信息，并只提供删除操作，而不无限显示处理中。
2. **假如** 用户删除资料，**当** 删除完成，**那么** 该资料及其派生内容不再用于后续问答。
   已有回答仍可显示当时保存的来源快照，但不能打开或恢复已删除的原始资料。

### 边界情况

- 用户上传不支持、空白、损坏或超过 50MB 的资料时，系统拒绝或标记失败，并给出可理解的原因。
- 用户单次上传超过 20 个文件时，系统拒绝超出限制的请求，并说明单次上传数量上限。
- 同一资料重复上传、处理中的资料被删除时，系统保持每项资料的最终状态可判断；删除等待必须有
  明确上限，运行工作进程失联时由持久化租约恢复机制接管，不得无限停留在 `deleting`。
- 相同内容的文件可作为独立资料重复上传；只有同一用户、同一知识库和同一 `Idempotency-Key` 的请求重放才复用首次结果，同键不同请求必须拒绝。
- 同一用户并发处理超过默认 3 份资料时，超出部分保持可恢复的等待状态；任务结束或工作进程失联回收名额后继续调度。
- 已进入 `running` 的任务发生工作进程失联时，系统必须关闭本次尝试，并依据剩余重试预算将任务重新排队或收敛为明确失败；不得只释放处理名额而遗留 `running/processing` 状态。
- 扫描 PDF、空 DOCX 或标准化后仅含空白的 Markdown/TXT 必须明确失败，不得生成空片段或嵌入。
- 资料处理完成前、处理失败后或已删除后，系统不得将其用作问答证据。
- 删除资料请求成功后，该资料立即从用户列表、详情和检索中隐藏；后台清理完成后保留不可查询的删除墓碑。历史回答仅显示保存的来源快照，不得据此访问、恢复或暴露已删除的原始资料。
- 对话流中断时，用户已提交的问题和已保存消息保持可恢复、可解释的状态。
- 用户会话失效、无权访问知识库或知识库已删除时，系统拒绝请求且不暴露其他用户资料。
- 删除包含处理中资料的知识库时，系统必须先停止或有界接管其运行任务并清理文件与派生数据，
  再完成知识库删除；从删除请求提交起该知识库及其资料即对用户和检索不可见。
- 请求超过对应接口类别的限流阈值时，系统拒绝本次请求，返回 HTTP 429、固定业务错误码和 `Retry-After`，且不得创建资料、消息或异步任务等业务副作用。
- 外部模型调用无法经过统一出口网关时，系统不得绕过网关直接请求供应商；必须按调用类型执行既定降级或收敛为明确失败。
- 统一出口网关检测到禁止外发的敏感数据但无法可靠脱敏，或脱敏组件不可用时，必须阻止请求离开系统；日志、异常和审计记录均不得包含触发失败的原始内容。
- 外部模型调用发生成功、重试、降级或失败时，日志只能写入规定的调用元数据白名单；即使内容已经脱敏，也不得记录请求或响应正文、提示词、用户问题、资料片段、文件名、请求头或凭证。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须允许用户注册、登录、刷新登录状态和退出登录。
- **FR-002**：系统必须允许已登录用户查看和更新自己的基本资料。
- **FR-003**：系统必须允许用户创建、查看、修改和删除仅属于自己的知识库；删除必须协调其资料、
  运行任务和持久化文件，不能依赖数据库级联直接跳过后台清理。
- **FR-004**：系统必须允许用户向自己的知识库批量上传 PDF、DOCX、Markdown 和纯文本资料。
- **FR-005**：系统必须为每份上传资料展示明确的处理状态、当前处理阶段、最终结果及失败原因。
- **FR-006**：系统必须异步处理资料，并使上传完成后不必等待资料处理结束。
- **FR-007**：系统必须为资料处理记录可追溯的阶段、尝试、错误和重试信息，并以持久化记录作为
  用户可见状态的依据；当前阶段完成、下一阶段激活和处理名额归属必须保持一致且可恢复。
- **FR-008**：系统必须使资料处理收敛为明确结果；中断、失败或重试耗尽时不得无限展示处理中。
- **FR-008a**：资料处理失败时，系统必须向资料所有者显示失败原因，并仅提供删除资料的后续操作；MVP 不提供重新处理或替换操作。
- **FR-009**：系统必须在将资料标记为可用前确认其内容、版本和可用于问答的资料片段一致。
- **FR-010**：系统必须允许用户查看自己知识库中的资料列表、资料详情和处理记录。
- **FR-011**：系统必须允许用户删除自己的资料，确保被删除资料及其派生内容不再用于后续问答，
  并保留历史回答中当时已保存的来源快照；删除提交后，任何仍在运行的处理尝试都不得继续写入
  该资料的持久化结果，等待运行尝试停止必须有超时上限，超时后由恢复机制安全接管；该快照不得
  用于访问或恢复原始资料。
- **FR-012**：系统必须为资料保留版本一致性信息，并仅使用当前已完成版本的内容回答问题；MVP 不提供面向用户的资料重新处理或替换功能。
- **FR-013**：系统必须允许用户创建、查看、重命名和删除属于自己的对话。
- **FR-013a**：系统创建对话时必须绑定一个当前用户有权访问的知识库；MVP 不提供不绑定知识库的纯聊天对话。
- **FR-014**：系统必须允许用户在绑定知识库的对话中发送消息并连续追问。
- **FR-015**：系统必须仅在当前用户有权访问且资料已完成处理的知识库范围内查找问答证据。
- **FR-016**：系统必须为每条基于知识库的回答保存并展示来源资料、资料版本及可定位的信息。
- **FR-017**：系统在找不到相关资料或证据不足时，必须明确告知用户，不得将推测表述为知识库结论。
- **FR-018**：系统必须以流式方式展示回答，并在传输中断后保留可解释的消息与处理状态。
- **FR-019**：系统必须保存用户的对话历史，并只向对话所有者展示该历史。
- **FR-020**：系统必须拒绝用户对不属于自己的知识库、资料、任务、对话、消息或引用的访问与操作。
- **FR-021**：系统必须为用户提供一致、可理解的成功、失败和权限不足反馈。
- **FR-022**：系统必须通过稳定、版本化的资源接口向客户端提供业务能力；客户端不得直接访问资料存储、任务执行或持久化数据。
- **FR-023**：系统必须保持界面、业务规则、数据读写与后台处理的职责边界，避免将授权或核心业务规则仅置于客户端。
- **FR-024**：系统必须拒绝单个文件超过 50MB 的上传请求，并向用户说明文件超出大小限制。
- **FR-025**：系统必须拒绝单次包含超过 20 个文件的上传请求，并向用户说明单次上传数量上限。
- **FR-026**：系统必须在服务端实施可配置的分级请求限流：注册和登录同时应用每来源 IP 20 次/5 分钟及每规范化邮箱 HMAC 摘要 5 次/5 分钟的默认阈值；刷新会话同时应用每来源 IP 20 次/5 分钟及每 refresh token HMAC 指纹 5 次/5 分钟的默认阈值；资料上传默认每用户 10 次/10 分钟；问答默认每用户 20 次/分钟；其他已认证接口默认每用户 120 次/分钟。所有阈值必须允许通过配置覆盖；任一适用阈值超限时必须返回 HTTP 429、固定业务错误码及 `Retry-After`，且不得产生业务副作用；原始邮箱和 refresh token 不得写入 Redis、日志或指标。
- **FR-027**：所有发往外部 LLM 或模型供应商的 Embedding、Query Rewrite、Reranker 和回答生成请求必须经过统一出口网关；网关必须集中执行供应商与模型路由、凭证注入、数据脱敏、超时、重试、既定降级及调用元数据审计。业务服务、后台任务和模型适配器不得持有绕过网关直连外部供应商的调用路径。
- **FR-028**：统一出口网关必须在外部请求发送前执行数据脱敏，并采用默认拒绝策略：当检测到禁止外发的敏感数据却无法可靠脱敏，或脱敏组件异常时，系统不得向外部供应商发送请求；只能记录不含请求原文和敏感值的失败元数据，并按调用类型执行既定降级或收敛为明确失败。
- **FR-029**：外部模型调用日志必须采用严格元数据白名单，只允许记录 `trace_id`、调用 ID、经不可逆处理的用户或租户标识、调用类型、供应商、模型、开始与结束时间、耗时、状态、错误分类、重试次数、输入与输出 token 数量及载荷字节数。日志、异常和审计记录不得保存请求或响应正文、提示词、用户问题、资料片段、文件名、请求头、凭证及其可逆摘要；脱敏后的正文同样不得写入日志。
- **FR-030**：系统必须在异步解析后拒绝标准化文本为空的资料，将资料和任务收敛为 `failed`，持久化稳定业务错误码 `20010 EMPTY_DOCUMENT` 及可理解的安全提示；空资料不得进入分块、嵌入或检索阶段。
- **FR-031**：系统必须允许用户将内容相同的文件作为彼此独立的资料上传，内容哈希不得作为业务唯一键；客户端可为批量上传提供 `Idempotency-Key`，同一用户、同一知识库和同一键的重试必须返回首次已接受结果，不得重复创建资料、任务或文件对象。
- **FR-032**：系统必须将单个用户同时处于 `processing` 的资料数量默认限制为 3，阈值允许通过配置覆盖；每份资料首次进入 `processing` 时必须通过数据库事务原子获取一个资料级名额，并跨 parse、chunk、embed、finalize 阶段持续持有，直到资料完成、失败、取消、删除或因工作进程失联被恢复任务回收；未获名额的资料保持可恢复的 `pending`/`queued` 状态而不得丢失。
- **FR-033**：批量上传必须先校验整批文件；任一文件格式不支持、超过单文件大小限制或整批数量超限时，系统必须拒绝整批请求并说明原因，不得创建其中任何资料、任务、幂等结果或持久化文件对象。
- **FR-034**：异步处理失败必须以稳定业务错误码和安全提示区分解析失败、空资料、文件持久化失败、嵌入失败、发布校验失败及无法归类的重试耗尽；详情查询仍返回成功的传输状态，并通过资料或任务的失败状态表达结果。

### 关键实体

- **用户**：拥有身份资料、登录状态、知识库、对话及其所有数据访问权限的主体。
- **知识库**：用户组织私有资料和发起基于资料问答的容器。
- **资料**：用户上传到知识库的原始内容，包含处理状态、版本和可诊断信息。
- **资料处理任务**：资料在各处理阶段的持久化记录，包含状态、尝试和错误信息。
- **资料片段**：从已完成资料的特定版本生成、可作为问答证据的内容单元。
- **对话**：用户在特定知识库范围内进行连续问答的容器。
- **消息**：对话中的用户提问或系统回答。
- **回答引用**：回答与其来源资料片段之间的可追溯关系；资料删除后保留当时的来源快照，以供核验但不恢复原始资料。

## 成功标准（必填）

### 可衡量结果

> SC-001～SC-007 仅用于产品发布后的成功度观察和独立产品验收，不属于本功能的自动化测试、
> 阶段门禁或发布阻断条件。实现任务不得为这些量化值建立固定评测集、比例断言或性能阈值门禁；
> 其底层功能行为仍必须依据对应 FR 和用户故事通过确定性的单元、集成、契约或端到端测试验证。
> SC-008 是明确的自动化出口安全门禁，不受此说明影响。

- **SC-001**：在正常服务负载下，95% 的支持格式资料上传后 10 秒内向用户显示已接收及明确的处理状态。
- **SC-002**：在正常服务负载下，95% 的不超过 20 MB 的支持格式资料在 5 分钟内达到已完成或明确失败的最终状态。
- **SC-003**：使用包含已完成资料的测试知识库时，90% 的相关提问在首次回答中包含至少一条可定位的来源引用。
- **SC-004**：在无相关资料的测试问题中，100% 的回答明确说明缺少知识库证据，且不提供伪装为资料结论的内容。
- **SC-005**：跨用户访问知识库、资料、任务、对话或引用的授权测试全部被拒绝，且不返回受保护内容。
- **SC-006**：90% 的试用用户能够在首次使用时于 10 分钟内完成创建知识库、上传资料并发起一次问答。
- **SC-007**：对已完成资料的问答中，95% 的用户可在两次交互内打开或定位到回答引用的来源资料。
- **SC-008**：自动化出口安全测试中，100% 的外部 Embedding、Query Rewrite、Reranker 和回答生成请求经过统一出口网关；绕过网关及脱敏失败的请求均未离开系统，全部调用日志仅包含允许的元数据字段且不包含请求或响应正文及敏感值。

## 假设

- MVP 面向个人与轻量团队；每个知识库归属于单一用户，团队共享与协作编辑不在本期范围。
- 首期仅支持 PDF、DOCX、Markdown 和纯文本资料；旧版 `.doc`、图片、音视频、网页抓取和扫描件文字识别不在本期范围。
- 用户以邮箱和密码创建账号；第三方单点登录不在本期范围。
- MVP 不提供忘记密码、邮件重置或验证码重置流程。
- 用户在上传后允许资料异步处理，并能接受在处理完成前该资料不能参与问答。
- 正常服务负载以单个用户的轻量资料集合为基准；超大文件、极高并发和跨知识库聚合问答不在 MVP 范围。
- MVP 默认将原始资料与解析中间产物保存在挂载到 `/data/orionamesh` 的本地持久卷；数据库仅保存相对对象键，不保存宿主机绝对路径。对象存储适配器属于后续部署扩展。
- MVP 不提供资料重新处理或替换接口；该能力及面向用户的版本切换流程延期至 Phase 2。
- 每个对话必须绑定一个用户有权访问的知识库；不绑定知识库的纯聊天不在 MVP 范围。

## 宪章影响

- **租户与授权**：所有资源访问由服务端根据当前用户及已授权知识库判定；资料片段、任务和派生内容保留用户归属。所有片段读取必须经过统一数据访问边界：问答证据查找强制限制用户、知识库、当前版本和完成状态，流水线内部校验强制限制用户、知识库、资料和精确版本。
- **状态与版本**：资料处理状态及尝试记录是唯一业务真相；处理必须收敛为明确结果。仅当前已完成版本可参与问答；版本字段和清理边界作为后续重处理能力的一致性骨架保留，MVP 不开放重处理或替换入口。
- **检索与引用**：问答仅使用可验证的资料证据；回答保留可定位引用，证据不足时明确告知用户。
- **安全与可观测性**：凭证和敏感资料不得出现在不应公开的反馈或诊断信息中；处理状态、失败原因和耗时必须可诊断，增强能力不可用时必须安全降级。
- **外部模型边界**：所有外部模型调用统一经过出口网关，先脱敏再发送；脱敏失败默认拒绝，业务代码不得旁路直连。模型调用日志只保留严格白名单内的调用元数据，不记录任何请求或响应正文。
- **架构与 API 契约**：客户端经版本化资源接口使用服务能力；界面、业务规则、数据读写和后台处理职责分离，流式传输只用于单向消息展示。
